# RASUN Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver the approved local/testnet full-chain RASUN system.
**Architecture:** ERC20 checkpoints, immutable referral graph, permissionless batched daily settlement. NestJS reads chain and maintains replayable SQLite index; Vue clients send wallet transactions.
**Tech Stack:** Solidity 0.8.24/OpenZeppelin, Hardhat, ethers, NestJS/Prisma, Vue/uni-app, pnpm 9.
**Spec:** docs/superpowers/specs/2026-10-29-rasun-design.md

## Global Constraints
- One hundred million cumulative minted cap; initial two million split equally.
- UTC+8 days; frozen past balances; competition ranks; separate claims.
- Exact integer math, no server-controlled reward amounts, no mainnet deployment.
- Preserve keys outside Git; display unavailable and demo states truthfully.
- Existing isolated checkout is sufficient; no additional worktree.

## Review Focus
- Crossing day boundaries during pending settlement must not change history.
- Address churn, empty referral groups and zero eligible weights must terminate.
- RPC errors and reorgs must not leave fabricated or duplicate user data.
- Wallet account/network changes must invalidate stale transactions.
- Price-source unavailability blocks pool sales, not ordinary transfers or claims.
