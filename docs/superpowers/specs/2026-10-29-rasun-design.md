# RASUN 完整开发版设计

## 目标和范围

依据用户提供的《雷达RASUN需求文档.pdf》，在现有 pnpm monorepo 实现可本地部署、联调和验证的 BSC DApp、运营后台、API 与合约。用户已选择全链上计算和结算路线。本阶段不执行主网部署、不投入真实资产。交付包含启动文档、部署脚本、合约测试、API 测试、前端构建和功能检查，明确测试数据与真实链上数据。

## 路线

1. 全链上计算与结算：已选；后端只索引、查询、辅助触发公开结算，不决定收益，不持用户私钥。代价是排序和历史快照需要分批处理，结算存在延迟及 Gas 成本。
2. 链下计算、Merkle 链上领取：适合大规模索引，但依赖链下结果发布，不符合本次纯合约选择，故不采用。

沿用 Vue/uni-app H5、Vue 管理端、NestJS、Prisma SQLite、Hardhat/OpenZeppelin。以钱包为账户，不要求用户创建密码。管理端本阶段为只读监控；任何配置资产操作通过部署权限或钱包交易完成，不建立后端托管提款接口。

## 经济规则及本设计的明确取值

- 累计铸造量硬上限一亿枚，销毁不恢复发行额度。首发两百万枚，分别向矿工分配地址和流动性地址各发一百万枚。初始池比例是部署指导，不伪造五十万 USDT 的注资。
- 矿业释放第一月十万枚；每月按三十个自然日计。第 2–6 月较上月增加 10%，第 7–42 月增加 5%，第 43–78 月增加 3%，第 79 月起增加 1%，到一亿累计发行上限即停止。阶段切换时应用新阶段增幅。文档的第四阶段十个月与总上限冲突，以硬上限优先；最终一期截断。
- 链上按最小单位整数计算，月内每日量用累计差分分摊，避免三十次除法的累计漏发。每日 50% 持币、50% 推广；奇数最小单位归推广。
- 日界采用 UTC+8 零点，持仓取上一完整日结束前的链上余额。小于一枚不参与持币排名。按余额升序的竞争排名，即 1 + 余额严格更小的合格地址数量；同余额同排名，下一组跳号。宣传图中的“最佳区”是示例，不写死为 101 枚。
- 直推关系由受邀钱包自己发送交易绑定，一次绑定、不能自邀、不能形成环。邀请链接仅预填，不自动签名。推广只计算直属下级，不叠加下级团队。
- 推广权重：最大直推余额取立方根；其余直推余额 x 的权重为 x<=1000 时 10x，否则 10000+(x-1000)。最大余额并列时仅挑一个做立方根，其余照常。采用 18 位定点整数立方根。文档例子 A 约 43546.4159，C=90010；不得把 C 写成约 91000。
- 首发地址、零地址、销毁地址、合约自身及已配置交易池不参加挖矿。排除规则在矿业开始前冻结，避免任意改变已生成的历史收益。
- 买入税 3%：销毁、技术、运营各 1%；卖出税 5%：前述各 1%，DAO 2%。普通钱包转账不征交易税。额外卖出税按相对当日开盘价跌幅 >=10/20/30% 为 5/10/15%，一半销毁，一半转市值调控地址；税费以代币支付。
- 持币、推广收益独立领取，跨日可累积，不自动划走或自动质押。余额变化仅影响之后的快照。

## 合约结构及结算

Token：ERC20、发行控制、池识别、税费、累计铸造统计及历史余额检查点；首次转入新地址时登记地址。不能保留 owner 任意增发入口。发行控制器只向奖励合约铸造授权日额度。

ReferralRegistry：链上不可变邀请关系及绑定历史，按快照日过滤新邀请；绑定验证分步或有明确 Gas 预算，不能用无界递归。

MiningRewards：日终后由任何人发起按日顺序结算，读取固定日界之前的历史余额和当时地址集合。通过游标对地址配对、直推遍历分批计算权重及总权重，单次交易限制操作数，避免一笔交易遍历全网。只有全部权重完成才生成最终收益。任意人可继续未完成结算，不依赖某个后台账户。结算开始后发生转账、注册和绑定不能改变该日结果。

首版验收边界为本地/测试网最多 100 个参与地址的完整日结算，并记录操作数、交易数和 Gas。朴素排名为每日 O(N²)，分批不等于可无限扩展；不将该实现宣称可承载大规模主网。生产化必须另行验证排序结构与抗粉尘地址攻击、长期状态增长及持续结算预算。本阶段不靠偷偷限制钱包转账或切换链下收益来掩盖限制。

每类分配采用确定顺序累计比例差分，使已分配之和等于对应有效池；总权重为零时，该池不分给其他类别，保留为明确记录的未分配储备。领取使用游标和最大天数参数，允许分别或批次领取已结算天数，更新状态后转账，防重复领取及重入。API/UI 区分未结算、可领取、已领取。

PriceOracle：接口隔离价格参考，不允许用户提交价格决定税率。开发版提供明确标记的本地测试预言机；测试网真实交易模式必须配置可信适配器。生产适配器需要目标交易对、稳定币、流动性和抗操纵观察窗口后才能确定。UTC+8 开盘价必须来自日界之前可验证的历史观察，不能把当天首次访问价格冒充零点价格。缺少有效参考时，池卖出明确拒绝并返回原因，普通转账及奖励领取仍可用。测试网未配置可信适配器时，不宣称已支持真实资金交易。

## 后端与管理端

API 提供健康检查、公开网络配置、代币概览、发行进度、分页排名、钱包余额与算力、邀请数据、两类收益、领取历史、同步与结算状态。金额使用十进制字符串，链上计算使用 bigint；所有地址、分页与日参数做输入校验。

索引按确认区块同步，事件以链 ID/交易哈希/logIndex 唯一；维护区块游标与区块哈希，发生重组时回滚受影响记录再重放。数据库不作为发币权威。RPC 不可达时返回明确不可用状态，不用随机数字冒充数据。独立的显式 demo 模式可供界面演示，但必须显示演示标记且禁用真实交易。

管理端显示发行、销毁、税费、日结算进度、用户排名、邀请关系、事件与运行状态，支持分页和错误/空态。配置文件不包含私钥，不提供任意 SQL、任意调用或公开可写管理接口。

## 前端与视觉

参考 PDF 第 1 页宣传图：紫色到玫粉渐变、浅粉半透明卡片、金属质感品牌字、柔和霓虹与雷达轨道，文字优先清晰可读。移动端优先，同时适配桌面。

页面：总览、持币挖矿/排名、推广/邀请、收益记录；持币与推广各自提供领取按钮。总览显示余额、发行进度、价格和税率、网络与数据状态。邀请页可复制分享链接、确认邀请人后签名绑定。钱包拒签、网络错误、余额不足、结算等待、重复操作有明确反馈。

默认简体中文，提供繁体、英文、马来文、日文、韩文、俄文完整界面文案。连接 EIP-1193 钱包，响应账户/网络变化；交易只发送到配置的链与已部署地址，显示待确认、成功和失败，不以点击按钮当作成功。

## 验证与交付

合约覆盖发行阶段/截断/销毁后不重铸、日界、并列排名、低余额排除、推广样例/并列最大/循环邀请、批次无关性、结算时余额变化、两池精确分配、跨日独立领取、防重领、权限、买卖税和暴跌阈值/失效价格。使用小规模独立参考实现比对权重与金额。

API 验证真实本地部署的索引和钱包查询、错误输入、分页、重复事件与重组恢复。两前端构建并验证移动/桌面、切换语言、连接钱包、邀请和领取流程。最终明确哪些检查实测通过，哪些需要外部测试网 RPC/可信价格源。提供本地一键部署与配置生成，不提交私钥或运行数据库，不部署主网。

## 留给实现者的选择

合约拆分的具体文件、游标编码、数据库索引、组件拆分、图标、响应式断点与测试工具由实现者决定。若实测发现纯链上历史排名在合理规模不可用，必须记录 Gas 数据并提出调整，不能悄悄切到后台发收益。
